## 零、三段记忆

| 段 | 存在哪 | 谁管 |
|---|---|---|
| **共享记忆 User** | 工作区之外 | 人管。明确要求才写，Agent 不随便加 |
| **长期记忆** | `长期记忆/` + `摘要记忆/` + 信息库 | Agent 自己管理 |
| **短期记忆** | 上下文 | 只保留「注入的摘要 + 最近 300 条原文」 |

**四件事，别焊在一起：**

| 谁 | 干什么 | 什么时候 | 碰不碰上下文 |
|---|---|---|---|
| **Agent 自己** | 写摘要：把一段对话概括成条目 | 每日首轮／自己想写时 | 不碰，只落盘 |
| **注入器** | 每轮往消息末尾追加 `<memory-summary>` | 每轮 | 加一条 snapshot，不改原文 |
| **截断** | 把老上下文切掉 | **做周期总结时**，切到「上一个周期总结点」之前 | 真删 |
| **事件碎片** | 主动检索 | 被调用时 | 不碰，只返回几条 |

把摘要在压缩时顺手生成，等于拿摘要当压缩的副产品——那不是摘要，是压缩。摘要必须是独立的一次思考。

**全部上下文另存一份 `总上下文.json`。**

## 一、摘要记忆：7 → 7 → 7 → 半遗忘

### 四层节奏

```
第1层  日摘要      每天一份         26.11.24/26.11.24摘要.json
第2层  周总结      7 个日 → 一份    26.11.16～26.11.22/…记忆文档.json
第3层  周期总结    7 个周 → 一份    26.10～26.11/…周期文档.json
                                  ↑ 做这一步时，顺手把「上一个周期总结点」之前的上下文截断
第4层  年度/半遗忘 7 个周期 → 一份  2026/2026年度文档.json，不再注入
```

**截断不是定时器，是周期总结的收尾动作。** 切点固定在**上一个周期总结落笔的那一轮**，保证切掉的每一段都已被摘要覆盖过。

### 命名规则

目录名与文件名同名，靠后缀区分层级。

| 层 | 目录 | 文件 |
|---|---|---|
| 日 | `26.11.24` | `26.11.24摘要.json` |
| 周 | `26.11.16～26.11.22` | `26.11.16～26.11.22记忆文档.json` |
| 周期 | `26.10～26.11` | `26.10～26.11周期文档.json` |
| 年 | `2026` | `2026年度文档.json` |

**核心动作**：每次再总结 = 把下层记忆拉进「下属记忆」文件夹 → 生成同名文档 → 两者一起装进区间文件夹。

### 注入配比

```
7 个日摘要 + 7 个周总结 + 7 个周期总结 + 最近 300 条原文
```

每轮都注入，不是检索。半遗忘区不注入，只在明确要求时调取。

## 二、事件碎片

### 一条 = 一个事件，存储分两半

**事件本体** `<事件名>.json`：

```json
{
  "name": "配音做到95%",
  "time": "2026-11-23",
  "type": "技术",
  "summary": "一句话总结，用来快速判断用不用得上",
  "detail": "详细正文，平时不检索所以可以写细",
  "links": ["DSH插件insert"],
  "linkCap": 3,
  "created": "2026-11-23T13:59:32.013Z"
}
```

**会变的指标** `_index.json`（每个月份目录一个）。分数会随每轮总结变动，写进文件名立刻过期，所以抽出来：

```json
{
  "updatedAt": "...",
  "events": {
    "配音做到95%": {
      "weight": 1, "score": 100, "rating": 0, "level": "L0",
      "hits": 1, "linkedHits": 1, "lastTouch": "2026-11-24", "missStreak": 0
    }
  }
}
```

### 四个数

| 字段 | 叫法 | 是什么 |
|---|---|---|
| `weight` | **权重** | 被关联权重系数。被关联一次 +1，参与联想总额度计算 |
| `score` | **分数** | 频率系数。初始 100，**总结洗牌时 −20 / +10 / 按赋分加减** |
| `rating` | **评分** | 评定分。**直接调用 +3、被关联 +1**，初始 0 |
| `level` | **层级** | L0~L5 + 半丢弃，L0 最高 |

**日常调用加的是评定分，总结洗牌动的是频率系数。** 两个分各管一件事，不要混。

其余字段：`time` 发生时间；`type` 类型；`summary` 检索入口；`detail` 细节；`links` 关联事件名；`linkCap` 单次最多牵出几条。

### 七层

```
L0 → L1 → L2 → L3 → L4 → L5 → 半丢弃
↑ 核心                        半遗忘 ↑
```

低层被调用时有倍率：L3 ×1.5、L4 ×2、L5 ×3、半丢弃 ×5。

### 升降级（发生在「事件总结」时）

**L0**

- 被调用过：评定分前 30% → 频率系数 +10，留 L0；其余 → −20，降 L1
- 完全没被调用 → −40，直接降 L2

**L1 ~ 半丢弃**

- 评定分前 30% → 频率系数 +20，再按 10 分制赋分加一次，升一层
- 被调用过 → 保持
- 一次没调用 → −10
- 连续两次没调用 → 再 −20，降一层

**批量例外**：只有 L3/L4/L5 允许把评定分最高的几个直接升入 L2；其他层只能一个一个升。

### 调取规则

| 场景 | 规则 |
|---|---|
| **半丢弃层** | 只有人类明确要求才调 |
| **关联联想** | 单次牵出的**被关联权重之和**不得超过上限（默认 10）；每条另受 `linkCap` 限制 |
| **直接调取** | 只从 **L0~L1** 找，Agent 判断没有目标事件才下探一层 |

### 什么时候处理

人类说「处理你自身记忆」时 → 把上次总结到这次的**全部上下文**做一遍事件碎片处理，写进长期记忆。

## 四、实现的边界（要清楚，不然会误判）

1. **检索是关键词匹配，不是语义。** `summary` 和 `type` 是入口，必须写足。
2. **摘要是 Agent 自己写的**，引擎只建目录、落文件、算检索顺序。引擎不会自己总结。
3. **会话可能没有每轮时间戳**，只有 `lastMessageTime`。"昨天"要靠人界定范围，引擎只按给定范围切。
4. **分数会随每轮总结变**，所以不要依赖文件名里的数字，一切以 `_index.json` 为准。
